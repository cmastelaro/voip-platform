# Asterisk Realtime reference

Endpoint configuration is stored in PostgreSQL and read by Asterisk on demand.
Provisioning is a database write; no reload is required.

ODBC is not a preference. PJSIP objects resolve through Asterisk's sorcery
layer, whose realtime wizard is implemented only against `res_config_odbc`.
The native `res_config_pgsql` driver does not work for PJSIP configuration.

## Configuration files

| File | Mounted at | Purpose |
|---|---|---|
| `odbc.ini` | `/etc/odbc.ini` | DSN: driver, host, port, database |
| `res_odbc.conf` | `/etc/asterisk/` | Asterisk's connection pool for that DSN |
| `extconfig.conf` | `/etc/asterisk/` | Maps realtime families to an ODBC connection |
| `sorcery.conf` | `/etc/asterisk/` | Maps PJSIP object types to realtime families |
| `pjsip.conf` | `/etc/asterisk/` | Transports, and any statically-defined endpoints |

`odbc.ini` is a unixODBC file and belongs in `/etc/`, not `/etc/asterisk/`.

`extconfig.conf` and `sorcery.conf` are frequently confused. They operate at
different layers and both are required:

- `extconfig.conf` — *"the family `ps_aors` lives in the `asterisk` ODBC connection"*
- `sorcery.conf` — *"the PJSIP object type `aor` is fetched from the family `ps_aors`"*

## Driver name

The `Driver =` value in `odbc.ini` must match a **section name** in
`odbcinst.ini`, not the `Driver=` line inside that section. Debian provides
`[PostgreSQL ANSI]` and `[PostgreSQL Unicode]`; there is no plain
`[PostgreSQL]`.

```bash
docker exec pbx odbcinst -q -d     # driver section names
docker exec pbx odbcinst -q -s     # configured DSNs
docker exec pbx odbcinst -j        # which files unixODBC actually reads
```

Unicode is used here so that non-ASCII caller ID is handled correctly.

## Sorcery wizard precedence

Two behaviours cause most realtime failures.

**Declaring a wizard replaces the built-in default.** Declaring only
`endpoint=realtime,ps_endpoints` stops Asterisk reading endpoints from
`pjsip.conf` entirely. To use both sources, declare the config wizard
explicitly. Wizards are tried in declaration order.

**Section headers name the module that registers the object type**, not the one
that consumes it. `endpoint`, `auth` and `aor` are all registered by
`res_pjsip`. Only `contact` belongs to `res_pjsip_registrar`, and `identify` to
`res_pjsip_endpoint_identifier_ip`. Misfiling produces a configuration that
partially resolves — the endpoint is found, its AOR is not, and REGISTER fails
with a 500 and no useful error.

```ini
[res_pjsip]
endpoint=config,pjsip.conf,criteria=type=endpoint
endpoint=realtime,ps_endpoints
auth=config,pjsip.conf,criteria=type=auth
auth=realtime,ps_auths
aor=config,pjsip.conf,criteria=type=aor
aor=realtime,ps_aors

[res_pjsip_endpoint_identifier_ip]
identify=config,pjsip.conf,criteria=type=identify
identify=realtime,ps_endpoint_id_ips

[res_pjsip_registrar]
contact=realtime,ps_contacts
```

`contact` is realtime-only, so registrations from both file- and
database-configured endpoints persist to `ps_contacts`.

## Schema

Generated by Asterisk's own Alembic migrations from `contrib/ast-db-manage`,
version-matched to the Asterisk release. Run from a throwaway container so the
runtime image carries no migration tooling:

```bash
docker compose --profile tools run --rm ast-db-migrate
```

The migrations create the full Asterisk schema, including tables for legacy
drivers this project does not use (`sippeers`, `iaxfriends`, and others). Only
the `ps_*` tables are relevant.

Columns such as `direct_media` and `remove_existing` are PostgreSQL enum types,
so invalid values are rejected on write rather than silently ignored at load.

## Provisioning an extension

Three rows, and they should be written in one transaction — an endpoint without
its auth or AOR fails at registration.

```sql
BEGIN;

INSERT INTO ps_aors (id, max_contacts, remove_existing, qualify_frequency)
VALUES ('1002', 2, 'yes', 30);

INSERT INTO ps_auths (id, auth_type, username, password)
VALUES ('1002', 'userpass', '1002', '<generated>');

INSERT INTO ps_endpoints (
    id, transport, aors, auth, context,
    disallow, allow,
    direct_media, force_rport, rewrite_contact,
    dtmf_mode, callerid
) VALUES (
    '1002', 'transport-udp', '1002', '1002', 'from-internal',
    'all', 'ulaw,alaw',
    'no', 'yes', 'yes',
    'rfc4733', 'Carol <1002>'
);

COMMIT;
```

The endpoint is live on the next lookup. No reload.

A development seed lives in `infra/db/seed-realtime.sql`.

## Live registration state

Registrations are rows, not in-memory state:

```sql
SELECT id, uri, expiration_time, user_agent FROM ps_contacts;
```

This is what the admin portal reads to show who is online, without an Asterisk
API call.

## Networking

Asterisk runs with `network_mode: host` and therefore cannot resolve other
containers by service name. It reaches PostgreSQL through the host's published
port.

| Client | Address |
|---|---|
| `ast-db-migrate` (bridge network) | `postgres:5432` |
| Asterisk (host network) | `127.0.0.1:5433` |
| `psql` on the host | `localhost:5433` |

The host port is 5433 rather than 5432 to avoid colliding with a natively
installed PostgreSQL. It is set by `POSTGRES_PORT` in `infra/.env`.

## Diagnostics

Work down the stack — each command removes one layer from the problem.

```bash
# 1. unixODBC alone, Asterisk not involved
docker exec -it pbx isql -v asterisk-connector asterisk <password>

# 2. Asterisk's connection pool
docker exec -it pbx asterisk -rx "odbc show"

# 3. The realtime layer directly, bypassing sorcery
docker exec -it pbx asterisk -rx "realtime load ps_aors id 1000"

# 4. Sorcery resolution
docker exec -it pbx asterisk -rx "pjsip show endpoint 1000"
docker exec -it pbx asterisk -rx "pjsip show aor 1000"
docker exec -it pbx asterisk -rx "pjsip show auth 1000"
```

Step 3 is the key isolation: if `realtime load` returns the row but
`pjsip show aor` does not, the database and mapping are correct and the fault is
in `sorcery.conf`.

## Troubleshooting

| Symptom | Cause |
|---|---|
| `Data source name not found` | `odbc.ini` not mounted at `/etc/odbc.ini`, or DSN name mismatch |
| `Can't open lib ... file not found` | `Driver =` does not match a section name in `odbcinst.ini` |
| `Connection refused` | Wrong port — Asterisk needs the host-published port, not 5432 |
| `password authentication failed` | Credentials differ from `infra/.env` |
| Endpoint resolves, AOR does not | Object type filed under the wrong `sorcery.conf` section |
| Static endpoints disappear after enabling realtime | `config` wizard not declared alongside `realtime` |
| REGISTER returns 500 | Usually a failed AOR lookup or `ps_contacts` write; check `/var/log/asterisk/full` |
| Realtime endpoint absent from `pjsip show endpoints` | Realtime objects are fetched on demand; use a targeted lookup |

Bind-mounting a host path that does not exist causes Docker to create a
**directory** with that name. Asterisk then fails to start reading a directory
as a config file. Verify config files exist before `docker compose up`, and
check with `docker compose config`.
